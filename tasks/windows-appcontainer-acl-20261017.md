# شريحة هوية AppContainer وACL لكل تشغيل

الأساس `e40e198f4d4c5fbbcbdd7a512da08bcb0ad8c4f5`، والفرع الوحيد المسموح `fix/blocker-d-review-20261010`. تبقى الخطط السابقة ومهامها غير المكتملة دون استبدال. هذه قائمة مستقلة للشريحة المطلوبة، وليست إعادة تخطيط لـMission.

## العقد

هوية SID فريدة مشتقة أصليًا من اسم عشوائي لكل تشغيل، دون إنشاء ملف تعريف يضيف مجلدات كتابة خارج مساحة العمل. مساحة جديدة محلية NTFS داخل root يتحكم به broker موثوق، مع DACL محمية وصريحة تمنح SYSTEM وbroker التحكم وتمنح SID التشغيل فقط حقوق البيانات المطلوبة. لا منح لـALL APPLICATION PACKAGES أو وراثة ACL واسعة. انخفاض mandatory integrity لا يحل محل فحص SID/DACL.

المكوّن لا يطلق عمليات ولا يتصل بـMissionRuntime. الإطلاق في اختبارات Windows فقط، بواسطة fixture موثوقة صغيرة تتحقق من token الفعلية وLPAC وSID وغياب capabilities. لا تعديل لـVHD أو Job، ولا تفعيل backend أو تغيير `PROCESS_SANDBOX_UNAVAILABLE` / `RESOURCE_BLOCKED`، ولا main/tags/releases/Cloudflare.

## المخاطر والتقييد

إنشاء ملف تعريف AppContainer يعطي تخزين ملفات وسجل خارجيًا؛ لا يُستخدم هنا. اشتقاق SID لا يصنع token أو sandbox بحد ذاته؛ الإثبات الأصلي في harness منفصل، ولا يثبت أن backend المنتج متاح. لا تمثل اختبارات ملفات خارجية محددة برهانًا على منع كل كتابة في كل Windows: ACLs النظام وخدمات broker والـregistry والأجهزة والشبكة تحتاج مراجعة واختبارات مستقلة قبل التفعيل. لا يسمح إلا بقراءة runtime مصرح به؛ يُوثق أي وصول OS ضمني بدقة. حذف SID أو سحب ACL لا يغلق handles مفتوحة؛ يتطلب التنظيف انتهاء كل العمليات أولًا، ولا يجوز ادعاء إبطال token قائمة بمجرد تحرير SID.
