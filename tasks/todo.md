## قواعد أمنية غير قابلة للتنازل

- حسابان مخوّلان من Owner وبيانات اصطناعية افتراضيًا؛ البيانات الحقيقية تحتاج نطاقًا وتفويضًا صريحين.
- LLM يشرح فقط؛ قرار الثغرة لمتحقق مستقل حتمي قائم على الأدلة.
- سجل HTTP القابل لإعادة التشغيل يحفظ لكل رسالة/تبادل: method، URL، headers، request body، status، response headers/body، timestamp، test identity، request ID، وبصمة SHA-256.
- بيانات المهمات والمخرجات ملفات محلية منظمة ومصنفة بصلاحيات Owner فقط؛ لا تشفير عند السكون للملفات العادية، مع استثناء Vault المشفر. يحتفظ Owner بالبيانات حتى الحذف اليدوي.
- انتقال البيانات بين الأجهزة مباشر نظيرًا إلى نظير عبر VPN الخاص بـOwner أو اتصال مباشر؛ لا خادم بيانات مركزي أو rendezvous أو relay. عند عدم وجود مسار، تنتظر المزامنة ولا تنتقل إلى مسار بديل مركزي.
- قيم كلمات المرور والكوكيز والرموز الفعلية لا تظهر في الأدلة أو logs/stdout/DB/Mission history؛ تشير الأدلة إلى `secret_ref` فقط. تبقى القيم في Vault المشفر ومقيّد الصلاحيات حتى حذف Owner يدويًا.
- يجعل نجاح تسجيل Owner الدخول الجهاز موثوقًا، لكنه لا يمنح صلاحية عامة للأهداف؛ الوصول محصور بالقدرات المفوضة صراحةً من Owner وبالنطاق الحالي، مع بقاء ضوابط النظام والمنصة غير قابلة للتجاوز. الاسترداد الطارئ بمفتاح غير متصل يحتفظ به Owner وحده، لا بمسار مركزي أو KMS.
- Owner Instruction أعلى سلطة تطبيقية ضمن التفويض المصادَق عليه، مع استمرار فرض حدود النظام والأمن الثابتة.
