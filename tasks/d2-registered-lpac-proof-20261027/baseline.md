### Additional official registry API reference

[GetAppContainerRegistryLocation](https://learn.microsoft.com/en-us/windows/win32/api/userenv/nf-userenv-getappcontainerregistrylocation) returns a registry-storage `HKEY` for the current profile and takes desired access; the documentation says access for another user requires impersonation. The prototype must not enumerate or write private AppContainer registry mappings as a provisioning interface. The native storage gate will treat registry storage as unresolved unless exercised inside the verified AppContainer context through this documented API.

- Microsoft identifies `203` as [`ERROR_ENVVAR_NOT_FOUND`](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--0-499-). The launcher built environment entries in `SystemRoot, windir, PATH, TEMP, TMP` order. Microsoft requires environment-block strings to be sorted alphabetically by name, case-insensitive Unicode order ([Changing Environment Variables](https://learn.microsoft.com/en-us/windows/win32/procthread/changing-environment-variables); [CreateProcessW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw)). This is a confirmed contract violation and a likely cause of error 203; only a native rerun can confirm the fix.

- The sort fix is retained because the original order violated Microsoft's contract, but run `40472300344` proves sorting alone was insufficient. Microsoft explicitly documents that custom `lpEnvironment` blocks do not automatically propagate per-drive current-directory entries such as `=C:`; callers must add and sort them ([CreateProcessW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw)). The current environment omitted that entry while setting an explicit working directory. A local test-only correction now inserts `=X:=<child CWD>` first for drive-rooted workspaces and records only a boolean; it does not inherit the broker environment or expose path values. This is a documented missing item consistent with `STATUS_VARIABLE_NOT_FOUND`, but the correction is not yet verified on Windows. The four `STATUS_NO_SUCH_FILE` legacy launch failures still need separate diagnosis; broker-side image readability is not proof of effective LPAC access.
