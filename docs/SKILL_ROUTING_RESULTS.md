## دليل الأمان والاستئناف

يثبت `test_invalid_owner_is_rejected_before_router_provider_or_tool` أن المصادقة الفاشلة تمنع الانتقاء واستدعاء المزود. تختبر بوابة HTTP جلسة عامة بلا مالك، وCSRF مفقودًا، وعلمًا غير boolean وتعارض اختيار؛ لا يصل أي منها إلى إنشاء المهمة. لا تمنح الموافقة على المهارة أدوات إضافية، وتُرفض أداة نموذج تتجاوز سقفها.

اختبارات الاختيار تستخدم سجلات SQLite مؤقتة حقيقية، وتستبعد غير المعتمد، والمنتهي، والملغى، ومالكًا آخر، وتكشف التلاعب المتداخل بالتجزئة. تختبر مهارة إصدارها 2 كي لا يختلط إصدار المهارة بإصدار مخطط التوجيه 1. عند غياب أداة المهارة الأقوى تختار بديلًا مؤهلًا دون استدعاء أي أداة.

اختبار إعادة الفتح ينشئ MissionStore وSkillRegistry وAgentCore جديدة، ثم يستخدم `resume_mission` ومسار العامل المحمي للوصول إلى `GOAL_COMPLETED` بأدلة ومرجع مهارة ثابت وسلامة Mission. اختبار آخر يلغي المهارة بعد إعادة الفتح فيمنع dispatch؛ وآخر يبدل النسخة بين التوجيه والربط فيوقف المهمة قبل المزود. أما فشل الأداة المحاكى حتميًا فيحفظ الفشل والمرجع دون تبديل مهارة صامت. هذا إثبات إعادة فتح/استكمال داخل عملية الاختبار، لا إعادة تشغيل Windows فعلية.

المراجعة الآلية المستقلة الأولى وجدت إيحاءً زائدًا في وصف «تطابق واضح»، فصُحح إلى تطابق كلمات مؤهل وفريد مع تنبيه أن النفي والمعنى غير مفهومين. المراجعة النهائية لم تجد مانعًا أمنيًا ماديًا ضمن التغييرات؛ ليست شهادة أمان شاملة. ظل التحقق الحي قبل dispatch في المسارات الأصلية والنموذجية والمتوازية، ولم تُنفذ إجراءات Skill أو سكربتات المرجع.

## الاعتماديات والتراخيص وما لم يُثبت

لا تبعيات أو lockfiles جديدة، ولا API مدفوع أو استدعاء نموذج سحابي أثناء المهمة. يستعمل المسار ModelRouter والمزود المحلي الموجودين؛ اختبارات الميزة تستخدم مزودًا حتميًا للاختبار، فلا تثبت جودة تخطيط نموذج محلي حي. لم يُنسخ كود من المرجع؛ جذره MIT لكن المكوّن CTF-Sandbox-Orchestrator ذو GPL-3.0، ولذلك لم يُعامل المشروع كله كـMIT قابل للنقل بلا تمييز. التفاصيل والملفات المرجعية في [تقرير التدقيق](SKILL_ROUTING_AUDIT.md).

تبقى ثلاث فجوات مهمة: قبول Windows التفاعلي/المثبت غير منفذ لهذه الميزة؛ Blocker D بقي غير محلول مع إخفاقات AppContainer/المثبت الأساسية الموثقة في التدقيق؛ وفشل Workers Builds الحالي خارج نتائج Python. كما تبقى المطابقة لفظية محدودة لا benchmark دلاليًا عامًا، وارتباط قراءة الفهرس بواجهة `registry._connect()` الخاصة ملاحظة صيانة، وخلل ترتيب crash/lease الموروث غير مصحح.
