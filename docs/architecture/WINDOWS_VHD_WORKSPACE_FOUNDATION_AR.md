# مساحة Windows محدودة السعة: أساس مستقل لا يفعّل العزل

## ما تضيفه الشريحة

مساحة عمل بقرص افتراضي ثابت السعة لكل تشغيل، بهوية فريدة ومسار صورة ونقطة تركيب مولّدين داخليًا. الحد المطلوب يخص سعة القرص الافتراضي؛ المساحة القابلة لكتابة الملفات أقل بسبب بيانات نظام الملفات. ملف الصورة يستهلك أيضًا بيانات وصفية على المضيف، فلا يُقدَّم الحد باعتباره حدًا حرفيًا لكل بايت على المضيف.

المكوّن مخصص لكود broker موثوق ذي امتيازات. ليس أداة agent ولا API لتركيب قرص يختاره المشروع، ولا يثبت إمكانية تشغيل التطبيق المثبت دون امتيازات. الجذر المحلي الذي يحتضن الصور ونقاط التركيب يجب أن يكون تحت سيطرة broker وألا يمكن لأي مشروع أو عملية غير موثوقة تعديله. رفض reparse paths لا يحل سباقات تبديل المسارات إذا خُرق هذا الشرط.

الواجهة هي `WindowsVhdWorkspace.create(root, capacity_bytes)` في `workspace/windows_vhd_workspace.py`؛ يلزم broker ذو 64 بت على Windows وجذر NTFS محلي ثابت موجود مسبقًا. السعة عدد صحيح بين 64 MiB و4 GiB، بمحاذاة 1 MiB؛ تُرفض booleans والكسور والنصوص والقيم خارج النطاق قبل لمس الجذر. يستخدم التنفيذ fixed VHD لا VHDX، مع footer مقداره 512 بايت فوق سعة بيانات القرص.

تعرض النتيجة `run_id` و`image_path` و`mount_path` و`capacity_bytes`. التنظيف عبر `close()` أو `destroy()` أو الخروج من context manager، وإعادة `close()` بعد النجاح آمنة. يعرض `VhdWorkspaceError` كودًا منقحًا لا stderr أو مسارات خامًا؛ عند تعذر تأكيد التنظيف يكون `cleanup_required=True` و`error.workspace` هو الكائن المحتفظ به لإعادة محاولة موثوقة. يجب عدم إسقاط هذا الكائن أو اعتبار الخطأ نجاحًا؛ لا يوجد finalizer يخفي فشل التنظيف.

## دورة الملكية والأعطال

يولّد broker هوية التشغيل ويطلب حجمًا صحيحًا ضمن حدود المكوّن. يُنشأ قرص جديد مع تخصيص مادي كامل، ثم يُرفق دون تعيين حرف قرص تلقائي. لا تهيئة لقرص موجود: يجب إثبات ارتباط الجهاز بصورة التشغيل وسعته وحالته قبل Initialize/Format. تُركب مساحة الملفات داخل دليل خاص بالتشغيل، ولا تُسلّم مساحة جاهزة إذا فشل أي إعداد.

التنظيف صريح وليس عبر garbage collection، ولا يستخدم حذفًا متكررًا قد يجتاز مساحة مركبة. يجب إزالة التركيب وفصل القرص وإغلاق الملكية بأمان قبل حذف الصورة. عند الفشل، تكون النتيجة خطأ ظاهرًا مع هوية يمكن للجهة الموثوقة استردادها؛ لا يُطمس الفشل ولا يُعلن نجاح تنظيف غير مثبت. سقوط broker أو الجهاز يحتاج لاحقًا بروتوكول جرد واسترداد مستقلًا، وليس مبررًا لتمكين backend الآن.

## ماذا تثبت الاختبارات

تعمل بوابة Windows أصلية منفصلة على runner إداري، وتحفظ JUnit وSHA وصورة runner. يجب أن تثبت كتابة فعلية حتى رفض نظام التشغيل عند الامتلاء، وعدم تمدد الصورة، واستقلال تشغيلين متزامنين، والتنظيف الطبيعي وظهور فشل التنظيف. غياب القدرة أو الامتياز على Windows فشل اختبار لا skip. اختبارات Linux للعقود لا تُعد دليلًا أصليًا على حد القرص.

## ما لا تثبته

لا يوصّل هذا المكوّن بـMissionRuntime أو إطلاق عمليات المشروع. يبقى backend Windows غير متاح، وتبقى `PROCESS_SANDBOX_UNAVAILABLE / RESOURCE_BLOCKED` محفوظة. لا تزال AppContainer/LPAC وACL ومنع الشبكة وحصر جميع مسارات temp/profile/work والأبناء وحدود الموارد الأخرى وتكامل الإلغاء/الفنس/receipts والـbroker المنتج طبقات غير مكتملة. قدرة قرص ممتلئ على رفض الكتابة لا تمنع عملية بصلاحيات المضيف من الكتابة خارجه.

لا دمج إلى main ولا release أو tag أو تعديل Cloudflare ضمن هذه الشريحة. نجاح primitive ليس نجاح قبول Mission الكامل.
